# 真實 LINE 資料的隱私就緒門檻

狀態日期：2026-10-08。這是未來實作與驗收的設計門檻，**不是已完成的去識別化或敏感資訊過濾功能**。目前唯一可執行的 adapter 模式為 `disabled` 與合成資料 `mock`；真實帳號模式不存在。

## 1. 信任邊界

本機資料庫、唯讀 SQL、私有 tunnel 與「不公開 port」各自解決不同問題。只要 MCP 回覆被送給雲端 host，回覆裡的文字、名稱、ID 與 metadata 都可能離開本機。唯讀不表示沒有外洩；不落地快取不表示 host 不保留對話。

未來允許的資料流必須是：授權資料來源 → 本機範圍檢查 → 本機分類／最小化 → 可信本機預覽與核准 → 確認接收者與有效授權 → 輸出檢查 → 指定 host。任何 gate 失敗即停止，不回退到未過濾資料。

原有 `line_mcp_server.py` 能在另行設定後讀取原始資料，並非這個隱私邊界。不得將它直接接上遠端 bridge 來省略新 adapter 的 gate，也不得教 host 自行 shell 呼叫原核心取得被阻擋的資料。

## 2. 必須涵蓋所有出口

不能只遮訊息 `content`。至少檢查：

- 聊天室名稱、別名、類型、ID、時間、未讀數及存在與否。
- 發言者、聯絡人姓名與別名、通訊錄、成員關係、頭像或連結欄位。
- 歷史、搜尋命中、未讀取樣、來源參照、引用、轉傳與附件 metadata。
- 原樣 query、cursor、摘要、截斷標記、schema 範例與工具描述。
- `items` 內所有巢狀欄位、MCP 文字與 structured content、`_meta`、錯誤、例外、stderr／stdout、debug、trace、telemetry 與快取。
- 搜尋空結果、筆數與最新時間等側向線索。授權讀取某聊天室，不自動授權列出全部聊天或所有聯絡人。

未知欄位、新工具與未知錯誤預設不得攜帶原始資料出去；需在共用輸出邊界完成分類與驗證。安全錯誤只回傳穩定代碼，不包含資料庫路徑、SQL 參數、訊息片段或憑證。

## 3. 資料分類與必要限制

- 一般姓名、聯絡資訊、地址與日期仍可能是個人資料。要有特定用途與適當接收者授權，避免順手一併輸出。
- 病況、藥物、醫療交流、財務／信用／資產資訊、未成年人資訊，可能從自然語句、關係或跨訊息內容推得。只靠關鍵字或 regex 不足以全面辨識。
- 「人物 A」、遮住電話、移除姓名或雜湊 ID 都不保證匿名。時間、群組、職稱、事件與原句仍可能重新識別；雜湊短 query 也不是匿名證明。
- 對未知或低信心內容採拒絕或本機人工審閱，不能宣稱通用自動分類達到零洩漏。任何未過濾摘要也算資料輸出。
- 密碼、API key、access／refresh token、私鑰、OTP／驗證碼與其他憑證，不得成為一般「允許全部」或敏感內容揭露開關的可輸出內容。此插件不是認證資料搬運工具；另有必要的登入流程應使用專用安全機制。

## 4. 每次詢問處理方式與真實授權仍須實作

最新使用者偏好為每次相關資料呼叫前詢問「先去識別化」或「保留原文」，不是強制預設去識別。未選、接收方未知、scope 改變或取消時不傳資料；選原文也不能放行憑證類資料。選擇去識別後，若處理器尚未完成或分類不可靠，就不能聲稱已匿名或回退原文。

本版新增 mock 協商：`requires_confirmation` 沒有資料，展示接收方與範圍；回傳的 generation ID 是非持久、非秘密的示範識別資料，不是真人批准或真實存取 token。每輪 ID 綁定 scope，120 秒後禁止新執行／加入，已開始的合成操作可完成；完成後舊 ID 重播不可重新生效。所有結果仍標 `human_confirmation_verified:false` 及 `privacy_processing:not_implemented`。這不提供 live 授權，也不實作分類器。


未來如需使用者核准特定敏感內容，應提供**本機可信介面**，先在資料離開裝置前讓使用者看見準備傳送的內容。不能先把原文回傳給 LLM，再問使用者能否傳送，因為那時傳輸已發生。

核准至少綁定：具名接收平台／帳號／workspace、資料來源、聊天室、日期範圍、訊息或欄位、敏感資料類別、用途、有效期限及輸出預算。只能由可信使用者操作建立，模型、聊天訊息、網頁內容與工具結果不得自行批准。修改範圍或接收者需重新核准，逾期／撤回立即失效。

一般設定布林值如 `privacy_ready: true`、自行宣告「已匿名」、不帶範圍的 allow-all、模型產生的批准 token，均不能代替此機制。這些機制目前尚未實作；現有 adapter 會拒絕未知的核准或資料庫設定。

本機預覽也需自己的安全設計：不自動上傳畫面或內容、不加入遙測、不將批准內容寫入寬鬆日誌；清楚顯示接收者及資料，避免預選全選，支持撤回與到期。

## 5. 授權、預算、效能各自驗收

- 明確聊天室 allowlist、日期界線與工具權限在讀取前檢查；輸出還需再檢查。聯絡人及聊天室探索應是獨立權限。
- 每份成功交付的資料／狀態 payload 都計入 byte 預算，訊息另計筆數；相同請求合併只省 backend 工作，duplicate 仍各計一份。固定空資料的拒絕／disabled envelope 不累計 session bytes，故不能宣稱所有網路傳輸 bytes 都有總配額。重複、跨工具、並行與分頁不能放大核准資料量。
- 目前 gate 是程序內限制。若未來有多程序、多連線、服務重啟或多平台共用，應重新設計授權及累計預算的生命週期，不能宣稱當前實作已覆蓋。
- 失敗、取消、過期、資料更改與大項目被阻擋時預設保守失敗；不得自動換入口、放寬範圍、提高上限或重啟繞過。
- 完成結果不快取；進行中合併的資料亦只應短暫存在記憶體。這不保證記憶體已安全抹除，也不控制作業系統 swap／crash dump 或 host 的保留政策。

## 6. 接真實資料前的驗收清單

以下全部是待完成條件，不是本版已通過的聲明：

- [ ] 逐欄資料流與威脅模型，涵蓋查詢、回覆、所有工具、錯誤、metadata 及 host 的二次使用。
- [ ] 共用且無法旁路的輸出 gate；禁止 raw 核心、debug 入口、任意檔案及 shell 替代讀取。
- [ ] 分類／最小化策略的失敗行為；含醫療、財務、未成年人、憑證及語境推斷的合成反例，不把 regex 視為完整保護。
- [ ] 本機可信預覽、具接收者及範圍的限時授權、撤銷；原文不會先送往模型要求核准。
- [ ] 欄位深層、巢狀資料、空結果、超長內容、Unicode、跨頁、跨工具、並行、取消、exception 與未知欄位的外洩測試。
- [ ] 負面測試證明無憑證、原文、姓名、路徑或敏感 metadata 出現在未授權的 payload、錯誤、日誌與 trace。
- [ ] 原始訊息中的 prompt injection 不會改設定、取得批准、擴大資料範圍、呼叫外部網路或改變接收者。
- [ ] Windows reader 真實相容性及授權測試，與 mock 結果清楚分開。未支援的平台不以錯誤推測成可用。
- [ ] 選定平台的實際方案／地區／workspace 權限、傳輸方式、保留和模型資料使用規則，讓使用者審閱。
- [ ] 用合成資料測試 host 安裝、認證、工具發現、停用、撤銷與斷線；再取得首次真實資料傳輸的具體批准。

不得用測試總數、唯讀 annotation、封鎖一個 regex 範例或「資料庫還在自己電腦」替代以上檢查。

## 7. 此版本實際保護與仍有的限制

此版本透過沒有 live 模式、拒絕資料庫路徑與未知設定、固定合成來源，避免 adapter 接觸真實 LINE；通用錯誤與預算是額外的本機防線。它沒有完成上述分類、去識別化、可信預覽、核准 UI 或多 host 授權控制。

若未來建立 tunnel，工具結果仍會經過雲端平台；官方 Secure MCP Tunnel 的私有連線設計不等於資料留在本機。[OpenAI 官方連線模型](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) Gemini Keep Activity 及相關資料處理則需依實際帳號與當時設定重新評估。[Google 官方隱私中心](https://support.google.com/gemini/answer/13594961?hl=en)
